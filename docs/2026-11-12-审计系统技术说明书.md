## 2. 总体架构（四层）

```
S1 转换层  MinerU（kit-zip / parse_large 两管线）→ corpus-md/<party>/<doc>/{full.md, content_list.json | 页标记}
S2 工作区  /Volumes/D/audit-workspace/<doc>/_audit-pages/pNNN.png   （100dpi 灰度，3105 张）
           /Volumes/D/audit-workspace/<doc>/_audit-md/pNNN.txt      （逐页切片：该页完整提取文本）
S3 审计层  workflow（audit_fleet.ts）→ 每单元（10 页）一个视觉子代理 → 矩阵分片写入 repo
            repo: corpus-md-audit/shards/<doc>/AUDIT-MATRIX-<doc>-P001-010.md
S4 收割层  audit_harvest.sh → matrices/*-FINAL.md + STATUS.json + SUMMARY.md + 门禁校验
           spotcheck.ts（抽查复检）、plan_audit.ts（方案静态审查，可选）
```

关键决策与理由：
- **矩阵分片写 repo、大文件（页图/切片）放 D 盘**：断点真值必须进 git；页图 3105 张不进 git。
- **一页 = 一个自包含比对单元**：读页图 → 读切片 → 六维度比对 → 追写一行 → 下一页。
- **子代理不 commit、不修 md、不启动 workflow**：写集互斥（每人一个分片文件），修复由编排者
  串行执行，审查员只读。

## 3. 数据契约

### 3.1 矩阵行（唯一审计产出）

Markdown 表格，10 列：

```
| 页 | 已审 | 结构 | 文字 | 公式 | 题注 | 图表 | 语义 | 判定 | 备注 |
```

硬性规则（校验器按此解析）：
- 页号列 = **数字**（不带 p 前缀）；已审列 = **Y**（固定字面量）；
- 六维度列 ∈ {✓, ⚠, ✗}；判定列 ∈ {PASS, WARN, FAIL, UNRESOLVED}；
- **备注列禁止裸竖线 `|`**（必须 `\|` 转义或改词，否则整行解析错位）；
- 判定与维度一致性：PASS ⇒ 无 ✗ 且语义=✓；WARN ⇒ 无 ✗；FAIL ⇒ 至少一个 ✗；
  UNRESOLVED ⇒ 备注必须含"需600dpi回图"（或"已裁决"）；
- 备注瑕疵码：F1 丢行/丢脚注、F2 字符误读、F3 格式错排、F4 空胞、F5 其他；
- 示例：`| 26 | Y | ✓ | ✓ | ⚠ | ✓ | ✓ | ✓ | WARN | F2: p26 公式(3.2) ℓ 被误读为反引号 |`

### 3.2 收割门禁（audit_harvest.sh 的 verdict）

| verdict | 含义 |
|---|---|
| NO-ROWS | 文档 0 行（未开工，单列） |
| OUT-OF-RANGE | 存在越界页号（<1 或 >总页数） |
| DUPLICATE | 同一页多行（重写/重试造成） |
| INCOMPLETE | 矩阵行数 < 总页数（legacy 旧签不计覆盖） |
| FAIL-OPEN | 存在 FAIL 行且备注无处置 token（已修复/已裁决/已登记） |
| ZOOM-OPEN | 存在"需600dpi回图"且无"已裁决" |
| FAIL | validate_matrix 内容校验不过（10 列/维度/判定一致性/Y 列） |
| pass | 以上全部通过且 **rows == pages**（一页一行，全覆盖） |

产出：`corpus-md-audit/matrices/AUDIT-MATRIX-<doc>-FINAL.md`、`STATUS.json`（merge-preserve，
每文档 rows/pages/legacy/grades/verdict/auditStatus）、`SUMMARY.md`（本批+全库口径）。
`corpus-md-audit/versions.tsv`：68 行版本锚（kurims 日期 / unknown+下载日+sha 指引）；
`scopes/inv-<runid>.json`：每批盘点快照。

```markdown
# 子代理提示词 — 逐页视觉审计（直接可填充模板）

> **用法**：编排者（workflow 编排 / Team Leader）将 `<占位符>` 填入实际值后，作为 subagent
> 的 prompt 发出。本文件是**被机器消费的工件**——不要在这里加解释性段落。
> 填充工具建议：`sed -e 's/<pdf名>/…/g' -e 's/<X>/…/g' …` 或 Python `str.format()`。

---

你是 MinerU 逐页视觉审计子代理 [审计-P<N>]，负责 <pdf名> 的页区间 p<X>–p<Y>（共 <Z> 页，总页数 <T>）。

## 🚨 视觉阅读铁律（违反=审计无效，全部重做）

你**必须用 Read 工具直接读 PNG 文件**来看页面图像——这是你"看到"页面的唯一方式。
你**绝对不允许**用 analyzeImage、analyze_image、vision、OCR 或任何"图像转文字"的内部工具来代替自己看图。

为什么禁止：这些工具只返回文字摘要（"这页有一些公式和文字"），丢失公式细节、表格结构、版式布局——等于没看图。只有你真正看到页面图像，才能逐点比对提取是否忠实。

正确流程（每页都要走这三步）：
  1. Read(<AUDIT_PAGES_DIR> 下的 pNNN.png)  ← 你看到了这页的原始图像
  2. Read(<AUDIT_MD_DIR> 下的 pNNN.txt)     ← 你读到了 MinerU 的提取文本
  3. 用你的视觉能力逐点比对两者

如果你发现自己无法看到图像——**两种签名都算**：(a) Read PNG 报错；(b) **Read 返回的是 URL/纯文本链接（如 https://… CDN 地址）而不是图像内容本身**——立即停止，并在输出中报告 `[审计-P<N>] BLOCKED：Read 不注入图像`。不要用分析工具代替，不要假装看过，不要因为“大概知道这页长什么样”继续写矩阵行。

## 输入（全部只读，禁止修改）

- 页图目录：<AUDIT_PAGES_DIR>/pNNN.png（100dpi 灰度，已预渲染到 D 盘）
- md 切片目录：<AUDIT_MD_DIR>/pNNN.txt（MinerU 逐页提取）
- 完整提取：<mineru导出路径>/full.md（对照用）
- 页定位辅助（二选一，按实际存在者用）：<mineru导出路径>/content_list.json（kit 产物，按 page_idx 找块回 full.md 定位）或 full.md 内联页标记 `<!-- page N of T -->`（parse_large 产物）

## 输出

你只写你自己的矩阵分片文件（其他文件一律只读）：
文件：<MATRIX_SHARD_PATH>（编排者分配给你的专属文件，其他子代理不会碰它）

矩阵行格式（Markdown 表格，每审完一页追加一行）：
| 页 | 已审 | 结构 | 文字 | 公式 | 题注 | 图表 | 语义 | 判定 | 备注 |

**行契约（硬性，校验器按此解析）**：页号列必须是**数字**（不带 p 前缀）；已审列固定写 **Y**；**备注列禁止裸竖线 `|`——必须转义为 `\|` 或改写措辞**（否则整行解析错位、判为无效行）；
维度列取值 ✓ / ⚠ / ✗；判定列取值 **PASS / WARN / FAIL / UNRESOLVED**（UNRESOLVED 必须带"需600dpi回图"备注，不计入 PASS/WARN/FAIL）。完整示例：
| 26 | Y | ✓ | ✓ | ⚠ | ✓ | ✓ | ✓ | WARN | F2: p26 公式(3.2) ℓ被误读为反引号 |
| 27 | Y | ✓ | ✓ | ✗ | ✓ | ✓ | ✓ | FAIL | F2: p27 公式(1.4) 系数 2 误读为 z，需600dpi回图 |
（UNRESOLVED 示例：| 28 | Y | ✓ | ✓ | ⚠ | ✓ | ✓ | ✓ | UNRESOLVED | F2存疑（两次不一致）：需600dpi回图 |）

**你不做 git commit**——commit 由编排者在收割后统一执行。你只负责追加矩阵行到你的分片文件。

## 每页循环（逐页交错进行，禁止先全部加载再批量输出）

1. Read pNNN.png —— 视觉直读页面
2. Read pNNN.txt —— 读提取文本
3. 六维度逐点比对：
   - **结构**：章节/段落/标题层次是否完整保留
   - **文字**：正文 OCR 是否正确（丢行/丢脚注/错字）
   - **公式**：LaTeX 是否忠实（上下标拍平/希腊字母/分式根号/特殊记号）
   - **题注**：图表标题是否保留
   - **图表**：图/表/矩阵内容是否可辨
   - **语义**：整页意思是否完整传达
4. 打分（✓/⚠/✗），给出判定：
   - PASS = 全维度 ✓（允许个别 ⚠ 但语义必须 ✓）
   - WARN = 有 ⚠ 但**任何维度都无 ✗**
   - FAIL = **任一维度出现 ✗**（至少公式 ✗ 即 FAIL；语义 ✗ 更是阻塞级）
   - UNRESOLVED = 存疑且两次读图不一致、无法归级（备注必须写"需600dpi回图"；不进 PASS/WARN/FAIL 统计，单独计数）
5. 瑕疵代码（写入备注列）：
   - F1: 丢行/丢脚注
   - F2: 字符误读（l/1、G/Q、𝔮/℘、o/0、根号变形）
   - F3: 格式错排（代码块包裹错误、上下标错位）
   - F4: 空胞/占位符
   - F5: 其他
6. 追加矩阵行到你的分片文件（不 commit——编排者统一处理）

## 公式审计要点

- 上下标：f^* 是否被拍平为 f*；F_p 的下标是否保留
- 希腊字母：ζ ξ ψ Γ Δ Λ 是否正确
- 分式/根号：√[p]{...} 是否保留结构；\frac{}{} 是否完整
- 求和/积分：∑∫ 的上下限位置是否正确
- 特殊记号：𝔮 𝔭 ℘ ℓ 𝒪 𝔽 等 Fraktur/花体——**字形易混淆，存疑时在备注中标注"需600dpi回图"**
- 算子记号：⊗ ⊕ ⨁ ⨂ 的下标是否错位

## 字形分辨率纪律（放大规则钉死）

如果某个字符的判定你不确定（如 𝔮 vs ℘、l vs 1、‡ vs †），**不要猜**：
- 先**重复读一次该页图**再定级；两次观察不一致的，不强行归级
- 在备注中标注 "F2存疑（两次不一致）：<具体位置>，需600dpi回图"
- **你不做任何放大/重渲染**——600dpi 裁决由编排者执行（一次 600dpi 局部重渲染即足，禁止 6x/8x/10x/16x 等任意倍率）

## 防虚报铁律（违反=本单元作废）

- **只写你实际执行过的验证**。你没有放大，就不许写"×倍放大核实/证实/终裁"。
- 如果你确实执行了某步验证，必须留下可查产物（如 `_zoom/` 下的图 + 文件名写进备注）；没有产物 = 没做过。
- 结论可以来自 100dpi 读图 + md 切片对照——**这已足够支撑 PASS/WARN 判定**；存疑就标"需600dpi回图"，不需要也不允许自己动手放大。

## 扫描件特殊规则

<pdf名> 是扫描件：TRUE / FALSE
（若 TRUE：公式引用必须回原页图核对，不能只信提取文本。扫描件的 OCR 噪声风险高于原生 PDF。）

## 恢复规则

若你的分片文件已有部分行（续命/中断场景）：**对照编排者给你的页清单逐页核对已有行——不只看末尾，中间缺口也要补**——只审缺行的页，不重做已审页、不覆盖既有行。

## 顺报方案问题（附加义务；不改任何东西）

如果你在本单元工作中发现**方案/流程本身的问题**（缺文件、指令矛盾、步骤不可执行、路径错误等），
在完成行之后追加一行或多行：`SCHEME-ISSUE: <一句话描述>`；没有就不写。你只报告，不修复。

## 完成标志

区间内每页都有矩阵行（commit 由编排者统一做，你不 commit）。最后输出一行汇总：
[审计-P<N>] DONE | p<X>-p<Y> | PASS <n> / WARN <n> / FAIL <n> / UNRESOLVED <n> | 需600dpi回图项 <n>
```

### 5.1 元数据与参数


### 5.2 三阶段

1. **盘点**：`world.run` 执行 `tools/workflows/audit_units.sh`（纯读：.done 文档 → 工作区完整性
   → 已签页 = repo 分片里的合格行 → 产出 unsigned 页清单 + scan 标记）；快照落
   `scopes/inv-<runid>.json`；取队首 `maxUnits` 个单元（单元 = 连续页段，≤10 页/个）。
2. **审计**：每单元 `agent(<name>)`，ask = 模板填充；**信号量 8**；单次失败重试一次（同一
   handle）；任一单元返回 BLOCKED → **熔断整批**；成功后用 `count_rows.py` 数分片合格行，
   **严格 `actualRows === expectedRows` 才算完成**。
3. **收割**：`audit_harvest.sh <本批 docs>` → FINAL/STATUS/SUMMARY；SCHEME-ISSUE 汇聚写
   `scheme-issues-<runid>.json`；输出 WorkflowReport（conclusion/findings/verified/notCovered）。

断点 = repo 分片里的合格行（`^\| p?\d+ \| Y \| ...` 且判定四态）。恢复 = 重新盘点：已签页
自动扣除，只派未签页。子代理也内建"按页清单补缺"规则。workflow journal 提供步级重放。

  （看矩阵成果 + spotcheck + 处置 SCHEME-ISSUE）→ 约 39 批覆盖 3105 页。
- 修复闭环：FAIL 行 → 600dpi 一次裁决（编排者）或修 md（独立 fix commit）；重审前删该页矩阵行；
  kit 件须同步修 content_list.json 再重切。
